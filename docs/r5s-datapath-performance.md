# R5S datapath performance

The combined firmware is a candidate for removable-SD testing. Physical forwarding rates, CPU utilization, thermal behavior, DMA coherency, and wire-level offload remain unmeasured.

## Architecture and profiles

The rollback multicore design places GMAC and the WAN application on core 0, logical LAN and supervision on core 1, and one B51 driver on each remaining core. Each core has one pinned NAT worker at priority 96. Logical LAN owns the bridge, ARP, DHCP, neighbor resolution and the forwarding dispatcher. Drivers retain exclusive access to their descriptor rings. Workers own their NAT tables and receive SPSC requests. Established endpoint affinity and the external NAT ID modulo four determine worker ownership in both directions. New endpoints are assigned using queue depth and active flow count. The dispatcher checks both queues against the worker's residency snapshot before releasing affinity.

Each cell shows a domain and its budget in microseconds. The common period is 1,000 microseconds.

| Core | Existing multicore | High-throughput |
|---|---|---|
| 0 | GMAC 400, WAN 400, worker 175 | GMAC 480, WAN 250, worker 240 |
| 1 | Supervisor 200, health 100, logical LAN 440, worker 200 | Supervisor 200, health 100, logical LAN 490, worker 180 |
| 2 | LAN1 650, worker 300 | LAN1 650, worker 300 |
| 3 | LAN2 650, worker 300 | LAN2 650, worker 300 |

Worker request queues coalesce notifications using an armed latch. The producer rechecks for backlog on each bounded poll, and the worker rearms at the end of a bounded activation. The LAN collector reports worker, PCIe and pool counters in the existing message sizes. For per-port TSO status in a TSO build, query the WAN lease from an on-link peer. The optional benchmark image adds a scheduler query while accepting legacy LAN requests.

The four budgets total 970, 970, 950, and 950 microseconds per core in the new profile. Priorities remain 110 for the supervisor, 105 for GMAC, 104 for WAN, 100 for health, 99 and 98 for the B51 drivers, and 97 for logical LAN. The build checks affinity and budgets, and Microkit validates the generated system. The optional benchmark SDK uses seL4 utilization accounting on each pinned worker core. It reports measured busy and idle PMU cycles and kernel scheduling-context postponements in sampling windows. Run `scripts/read-b51-udp 10.44.1.1 --scheduler --live` on that image. Samples remain unavailable until the worker publishes a completed window. [seL4 benchmarking guide](https://docs.sel4.systems/BenchmarkingGuide.html)

LAN bridge unicast forwards by reference through logical LAN. Router-addressed frames skip full-payload reflection hashing, since the bridge never adds them to its reflection history. Source learning checks one cached entry per ingress port before scanning the table. `R5S_BRIDGE_LOCAL_HASH=1` restores the previous lookup and reflection checks for A/B tests. In the combined build, eligible unfragmented IPv4 TCP/UDP replies carry the published lease revision directly from GMAC to the worker selected by the NAT port shard. GMAC owns the four request producers. Each worker maps only its own GMAC ingress queue. NAT policy, inbound peer validation and MTU checks still run in the worker. A stale lease revision rejects queued packets. Logical LAN finishes neighbor resolution and selects the LAN interface. On the return path, logical LAN sends eligible Ethernet frames directly to GMAC. DHCP, ARP, UDP status, Internet echo and exceptional packet layouts retain the WAN application path.

The optional `R5S_LAN_FAST_PATH=1` build maps eight additional SPSC request regions, one per LAN driver and NAT worker. Router-addressed IPv4 TCP/UDP enters the selected worker directly. The option uses a deterministic private-endpoint hash for TCP/UDP, including any routed fallback that reaches logical LAN. The normal profile retains load-aware assignment. Direct copied frames and references share the same FIFO, and congestion drops at that queue to avoid reordering. Both LAN domains read the route revision without write permission. Workers retain all NAT and packet validation. Logical LAN learns the source MAC from validated results before emitting packets and still owns neighbor resolution, egress, DHCP, ARP and bridge switching. Per-port FIFO order is preserved. Arrival order across two independent physical links during a host move remains unspecified.

Reference FIFOs carry markers for copied packets. The sender publishes the companion copy slot before the marker. The receiver consumes the slot only when the marker reaches the head of that same FIFO. The CPU profile places queue cursors and the wake latch on separate cache lines. This preserves queue order across pool exhaustion, bridge copies and worker request/result boundaries. Queue saturation drops at the affected boundary.

`R5S_WORKER_WAN_EGRESS=1` lets each NAT worker send validated IPv4 TCP and UDP traffic whose next hop is the WAN gateway straight to GMAC. The worker publishes references and copied frames into one private FIFO. Logical LAN supplies the gateway MAC and expiry through a read-only route snapshot and sends any required ARP probes. GMAC holds the FIFO head for up to one second while ARP resolves, checks the lease and link revision, and writes the Ethernet header before taking ownership of TX. Congestion or expiry drops at that queue. A flow whose route revision stays the same keeps one egress FIFO whether it uses a reference or a copy. On-link peers other than the gateway, LAN egress, ICMP, DHCP and bridge traffic keep the existing paths. Source learning from direct LAN ingress still reaches logical LAN as a metadata record; identical learns are coalesced (a 250 ms per-worker window plus a cross-worker batch applied once per MAC before the next frame result). Direct WAN egress skips dispatcher-side TCP aggregation. The switch defaults to off pending manual checks of cold ARP, WAN renewal and link loss under load.

The pool holds 1024 generation-tagged 2 KiB buffers on the default ring layout (512 on the 256/512-slot layouts, which have no room for more). Physical range starts at `0x24400000`. GMAC uses the low 32-bit identity DMA address. The two independent PCIe inbound windows translate that pool to `0x82000000` and `0x81100000`. By default, CPU mappings use Normal non-cacheable memory and conservative DMA barriers. GMAC private descriptors and payloads retain the existing cache maintenance. The bitmap allocator scans whole words and reserves one free bit atomically. External TX references return only on completion. A failed B51 doorbell after descriptor publication faults the driver and leaves the buffer reserved because DMA completion is uncertain. See the [shared DMA mapping and lifecycle](zero-copy-forwarding.md).

GMAC tracks shared-buffer addresses in driver-owned slot metadata, since descriptor writeback can replace the address fields. RX detaches the completed buffer before publishing it to another domain. TX returns ordinary shared buffers on completion and returns TSO fragments only with the final request ID. On a confirmed DMA stop, the driver retires references still assigned to that ring before restart. TX canceled at stop counts as dropped. A timed-out stop keeps the references reserved. The host model overwrites descriptor addresses on completion and exercises both successful and timed-out stops. [DWMAC descriptor writeback](https://github.com/torvalds/linux/blob/master/drivers/net/ethernet/stmicro/stmmac/dwmac4_descs.c)

Established outbound NAT, reverse NAT, related ICMP, private endpoint reuse and public port reservation now use worker-local indexes. Retired entries remain indexed until replacement to preserve reuse delays. New-flow slot allocation walks forward from a per-worker cursor so steady-state allocation with table slack is constant-time instead of rescanning from slot zero; the full table remains the bound. Public port reservation probes forward from a per-worker port cursor inside the shard's stride-4 lane, refusing any candidate still claimed by a live or retired mapping, so reuse delays hold and lanes stay disjoint across workers. Shared NAT scans eight expiry slots per maintenance call and rejects expired mappings during lookup even when their slots have yet to be visited. DHCP background maintenance scans sixteen leases per slice after the earliest deadline and handles expiry synchronously on DHCP requests before reusing addresses. Address changes and client releases still revoke the affected mappings.

## Hardware feature matrix

`R5S_ZC_CACHE=writeback` is an experimental A/B option for the SMP zero-copy profiles with 64, 128, 256 or 512 B51 descriptors. It gives every shared payload alias, including the kernel direct map, matching write-back attributes. B51 private DMA retains Normal non-cacheable mappings. The drivers clean and invalidate before RX ownership, invalidate before reading completed RX and clean after CPU changes before TX, including TSO fragments. Compare against `R5S_ZC_CACHE=nc` with the same ring, buffers and traffic. Validate payload integrity, receiver checksums, link recovery and throughput before deploying the write-back profile. The 256- and 512-descriptor write-back layout uses a shared pool at `0x24600000`. It separates the two non-cacheable private arenas with an aligned write-back span and reserves the padding. Each PCIe inbound aperture reaches its own private arena and the shared pool.

On images with direct LAN egress enabled, `scripts/read-b51-udp 10.44.1.1 --lan-tx --live` reports `direct_worker_tx_pending` on each LAN port. The four values include queued and DMA-owned submissions and saturate at 127. Older query sizes remain available. Pass `--lan-tx` with `--diagnostics` to `scripts/benchmark-router-board` to record those values during load.

`R5S_WORKER_LAN_EGRESS=1` enables direct reverse TCP/UDP TX to a resolved LAN port. Logical LAN publishes ARP and bridge bindings on its 10 ms maintenance tick. Each worker uses a single FIFO for shared references and copied frames per NIC. Each NIC validates the current route and policy revision before DMA, and drains unpublished direct requests on link-down. A worker that sees an in-progress route snapshot discards the current packet and keeps the client’s existing path selection. If the route is unresolved or moves, the worker switches to logical LAN only after the old FIFO has no outstanding submissions. A submission retires on hardware completion or a confirmed software discard. During that transition the worker drops new packets for the affected client. Returning to the direct lane is ordered per client: each fallback send arms a return token, and the client’s next frame takes the direct queue again only after its last fallback frame has completed transmission on the independent TX queues (so no direct frame can overtake a fallback frame); other clients keep flowing meanwhile. On a driver fault the NIC closes the lane and hands software queue cleanup back to its worker. A worker that was preempted during publication can discard the late request when it resumes. DMA-owned buffers remain subject to reset and transaction-drain checks. The option remains opt-in pending board validation of link moves, ordering and ARP expiry.

The `dma` and `combined` profiles publish the GMAC TX tail once per nonempty service sweep. Unpublished descriptors still consume ring space and cannot be reclaimed as completions. Set `R5S_GMAC_TX_BATCH=0` for immediate publication in an A/B build.

GMAC copied TX initializes the transmitted payload and mandatory Ethernet padding, then maintains only the cache lines covering those bytes. The host DMA model checks zero padding and the 64-byte and 1,536-byte maintenance spans for minimum-sized and MTU-sized Ethernet frames.

“Host-tested” covers the relevant descriptor, checksum or DMA model. Capability bits and driver source are reported separately from board behavior.

The optional build uses V3 RX descriptors and polls each ring in round-robin order up to the configured total RX batch. Each ring has its own cursor, private buffers and external-buffer ownership records. Both NIC driver domains retain exclusive ring ownership. The existing software dispatcher preserves NAT affinity independently of the hardware hash. The configuration hashes IPv4 and TCP/IPv4. UDP uses address hashing, which keeps fragments of a datagram on the same queue without relying on transport headers. B51 MSI-X still requires the ARM GIC ITS service missing from the native image. TX defaults to one no-close ring per NIC. `R5S_GMAC_TX_CHANNELS=2 R5S_WORKER_WAN_EGRESS=1` requests two polled GMAC TX channels. On the supported revisions, the driver requires HW_FEATURE2 to advertise two TX queues and channels and checks FIFO space before splitting it. Channel 0 serves normal traffic and TSO. Channel 1 serves direct worker WAN traffic with an independent 32-descriptor ring in the existing DMA arena. The status reader reports the provisioned TX channel count for this profile. `R5S_GMAC_RX_CHANNELS=2` requests a second GMAC RX channel. The driver checks the revision, HW_FEATURE2 and RX FIFO capacity, then splits the existing DMA arena into two 32-descriptor rings. Unicast stays on channel 0. The MAC sends accepted multicast and broadcast to queue 1, mapped to DMA channel 1. Both rings use the existing WAN receive and control paths. B51 status reports `wan.rx_channels=2` after activation. Compare against the same TX profile with `R5S_GMAC_RX_CHANNELS=1`. Validate broadcast and multicast delivery, DHCP, unicast order, ring wraps and link recovery on the board. `R5S_GMAC_HYBRID_IRQ=1` assigns INTID 59 exclusively to the GMAC domain. On a recognized DWMAC revision, the GMAC masks its RX interrupt, clears observed RX status, services up to four bounded sweeps, and unmasks reception before acknowledging the seL4 IRQ. The supervisor sends a poll notification on its first pass in each millisecond, covering quiet TX, residual backlog and revisions with interrupts disabled. This path can service supervisor shutdown during WAN-app faults. The status reader shows `wan.rx_interrupt.active` and `wan.rx_interrupt.observed`. Compare against `R5S_GMAC_HYBRID_IRQ=0` with idle, single-frame, sustained and link-recovery traffic. The default remains continuous polling. The GMAC PBL override checks revision and FIFO capacity. GMAC stays in low-address DMA mode. `R5S_GMAC_PBLX8=1` requests the burst multiplier used by pinned U-Boot, subject to the live GMAC revision and FIFO bounds for the RK3568 AXI width. The firmware reports Device Capabilities, live MPS and MRRS, and negotiated generation and lane width from both ends of each PCIe link. It uses the current fixed iATU windows and retains the trained Device Control values by default. The experimental build controls `R5S_B51_MPS` and `R5S_B51_MRRS` apply to both endpoints before bus mastering. MPS may not exceed the endpoint capability or the upstream port’s configured MPS. The firmware requires matching live link properties, verifies the write, and rejects startup on a rejected setting. Existing Ubuntu records show endpoint MPS 128 and MRRS 512 on LAN1. The pinned Realtek source requests MRRS 2048 when its SoC exception is inactive. Build separate images with MRRS 512, 1024 and 2048, and compare B51 link diagnostics and completion errors under identical traffic. `R5S_GMAC_RK3568_AXI=1` requests the Linux RK3568 AXI settings on recognized GMAC revisions. It keeps the 4-, 8- and 16-beat burst selections, sets the encoded read and write outstanding limits to 8 and 4, and enables mixed bursts. The driver programs the register while DMA is stopped. `R5S_GMAC_EAME=1` requests EAME (DMA_SysBus_Mode bit 11 in the EQoS register map) on recognized GMAC revisions 0x40-0x52, matching the value the pinned U-Boot EQoS init programs in its DMA performance configuration. Revisions outside the recognized range never request it. The WAN diagnostic reports the live bit inside `dma_capabilities.eame`. The option is enabled in the qualification image and defaults off in `combined` pending board comparison against `R5S_GMAC_EAME=0`. The `R5S_B51_RING` control accepts 64, 128, 256 or 512 slots. The 256/512-slot experiment uses two 3 MiB private pools and a 1 MiB shared pool between them. Each inbound iATU window covers its own private pool and the shared pool. The SMP kernel, fixed-frame allocation checker and image verifier use the matching Normal-NC range. The existing 64/128 layout remains available for comparison. The larger ring sizes need sustained board validation. The separate shared pool has quotas for all three drivers. `R5S_B51_DMA_BARRIERS=outer` selects outer-shareable barriers for B51 descriptor publication and observed completions in the SMP Normal-NC layout. It retains full barriers for MMIO, reset, initialization and GMAC cache maintenance. It requires a manual sustained DMA visibility comparison against the default `full` setting. Hardware flow classification and alternate payload caching are unqualified. No forwarding path assumes hardware NAT. [Linux DMA mapping rules](https://docs.kernel.org/core-api/dma-api-howto.html)

VLAN tag insertion and removal exist in both controllers (RTL8125 RxConfig VLAN strip bits and per-descriptor tags; GMAC MAC_VLAN_Tag_Ctrl) but are not enabled. The router workload uses fixed untagged subnets, so RX tag stripping without a VLAN-aware forwarding path would admit tagged frames into the native IPv4 path (a VLAN-hopping hazard), and TX tag insertion has no consumer. Tagged frames are safely classified as unsupported at `router-core/src/ethernet.rs:220` and dropped before parsing. This is a documented inapplicability, not a missing implementation; enabling the hardware would require a VLAN-aware forwarding design that this router does not have.

The WAN dump reports the GMAC link clock and MAC feature registers. The benchmark LAN dump decodes each ARMCLK divider and the observable DDR PHY 1x branch from the RK3568 CRU. It also reports the selected DDR PHY clock source and gate. The decoder omits rates for gated or unresolved sources, including the dedicated DDR branch, and discards samples when two consecutive CRU reads differ. The pinned Rockchip TPL file is `rk3568_ddr_1560MHz_v1.26.bin`. Collect temperature, recovery CPU/DDR telemetry and the PCIe link tree with `scripts/read-r5s-platform` from Linux recovery. Those readings characterize the recovery run. No PLL or thermal sensor control state is written. [Rockchip RK3568 TRM](https://opensource.rock-chips.com/images/2/26/Rockchip_RK3568_TRM_Part1_V1.3-20220930P.PDF)

RX checksum trust is limited to verified completion status, matching IPv4/transport protocol and software header/length/fragment validation. NAT adjusts translated checksums incrementally and preserves UDP zero. The optional `R5S_ZC_TX_CHECKSUM=1` path uses the selected per-port TX offload for shared-buffer frames after NAT validates them. The TX owner seeds only the relevant header fields immediately before DMA submission. GMAC uses zero seeds for full insertion. RTL8125 uses the folded IPv4 pseudo-header seed for TCP and nonzero-checksum UDP. UDP zero is preserved and frames without valid NAT provenance retain their software checksums. This option is disabled by default pending receiver-side wire checks. The TSO interface accepts explicit oversized TCP requests and retains all fragments until the whole request completes. Ordinary forwarding keeps its ingress segmentation. The opt-in GRO profile can pair two queued TCP references before NAT and can assemble an egress GSO request after NAT. `R5S_WORKER_GRO=1` enables the worker stage independently of `R5S_GRO=1`. It considers two adjacent references already in one FIFO and forms a bounded view with one canonical header and two payload ranges. Both segments still receive ordered, independent NAT validation and translation. A matching second segment can reuse the first segment’s slot after checking the live directional TCP tuple. A miss falls back to the ordinary index lookup. `R5S_NAT_PAIR_LOOKUP=0` disables reuse while preserving paired queue operations. A successful pair shares one receive and one result publication. The worker never waits for a second packet. A rejected segment or a full result queue takes the ordinary per-packet outcome. With the benchmark SDK, `read-b51-udp --scheduler` reports the count of successful worker pair publications. It requires plain non-fragmented IPv4 and TCP headers, matching addresses, ports, ACK, window, TTL, DSCP and MSS, contiguous sequence space, sequential IPv4 IDs, and an ACK followed by PSH+ACK. ECN, options, out-of-order ranges and retransmissions take the original packet path. The egress pairing holds one reference for up to the configured `R5S_GRO_HOLD_US` matching window and flushes by the end of the current completion sweep. The second buffer holds only payload, compacted in place for the NIC address alignment. Software GSO reproduces both input wire frames in a host test. `R5S_GRO_TSO=1` requests experimental hardware segmentation and needs independent capture before use as a default. `R5S_DRIVER_GRO=1` lets GMAC and B51 publish adjacent compatible references to the same direct worker queue in a single release operation. A driver can hold one CPU-owned reference while it continues the current RX polling batch. It flushes at the matching-window deadline, before copied traffic or another route, and by the end of the current sweep. It leaves transport validation and NAT in the worker. The benchmark image reports `gro.driver_pairs_published` separately from the worker and egress counters. NAT still applies state transitions and checksums at segment granularity. [TSO capability](tso-capability.md), [wire validation](tso-hardware-validation.md), [Linux offload semantics](https://docs.kernel.org/networking/segmentation-offloads.html)

### LAN2 upload and download comparison

Use the board-tested all-features image as the historical reference. Build the following three profiles from the same source for a controlled comparison. They share the release SDK, four-worker schedule, batches of 16, write-back shared payloads, two LAN TX queues and the original offload requests.

| Build profile | B51 RX queues per port | Descriptors per ring | Private DMA arena per port |
|---|---:|---:|---:|
| all-features | 2 | 256 | 3 MiB |
| lan-rx-single | 1 | 256 | 3 MiB |
| lan-rx-balanced | 1 | 128 | 1 MiB |

The ring depth setting also changes TX depth and the physical DMA layout. Each LAN port owns 176 shared buffers. One 128-slot RX ring leaves 48 buffers available when all its descriptors hold shared buffers. In-flight forwarding and TX consume that headroom. In the tested 2-by-256 layout the same reservation cannot cover all RX descriptors. A ready private descriptor migrates to the shared pool on rearm. A completed external descriptor gets a replacement or falls back to private storage. A single-ring idle poll now checks for a completion before requesting a migration buffer. Neither a WAN download gain nor an upload gain has been measured for the candidate.

The LAN2 driver can submit eligible client frames to the flow owner directly. The GMAC driver can dispatch eligible reverse NAT packets by translated port. The worker submits eligible results to the egress driver, which owns TX completion and reclamation. Exceptional traffic retains the logical LAN and WAN paths. Comparing multicast, management, or WAN app counters alone therefore misses traffic. GMAC reported one channel each way on the tested board. Requested TSO produced zero hardware frames in the supplied snapshot.

Run `iperf3 -s` on a wired peer on the upstream 10.0.1.0/24 subnet. From 10.44.1.100 set WAN_PEER to that peer's address and LABEL to the image hash. Use a fresh output directory for each run.

```bash
scripts/benchmark-router-board "$WAN_PEER" "results/$LABEL" --label "$LABEL" \
  --ping "$WAN_PEER" --bind 10.44.1.100 --interface enp4s0 \
  --diagnostics 10.44.1.1 --queues --seconds 30 \
  --case tcp-1 --case tcp-4 --case tcp-8 \
  --case tcp-reverse-1 --case tcp-reverse-4 --case tcp-reverse
```

Schema 12 reports per-ingress allocation failures and private RX packet and byte copies. One failed allocation may occur without dropping the packet. Software-stage and broadcast copies remain in the existing aggregate counters. The benchmark omits unavailable fields and uses null deltas for decreasing counters (possible wrap or reset) or saturated copy/allocation counters. Start a fresh measurement after a reboot. The live pending descriptor gauge covers all selected TX rings. Independently published submission/completion totals can disagree with that gauge.

Compare receiver Mbps, retransmissions and p95 latency in each direction across repeated runs. Use the same Speedtest server separately for Internet comparison. For LAN bridging, connect a 2.5 GbE peer to each LAN port and confirm both negotiated rates before running the same traffic patterns. Physical throughput and runtime activation of experimental settings require manual verification.
