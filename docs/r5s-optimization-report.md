# R5S throughput optimization — final report

Delivery report for the multicore and hardware-accelerated network throughput
program on the NanoPi R5S (RK3568) seL4/Microkit router. Architecture, profile
semantics and the hardware matrix live in
[r5s-datapath-performance.md](r5s-datapath-performance.md); this document is
the implementation summary, artifact inventory and verification record.

All physical forwarding rates, CPU utilization, DMA coherency and wire-level
offload results remain unmeasured. Board testing and SD flashing are manual
operator steps. Nothing in this report claims line-rate forwarding.

## 2. Profiles and build configuration

`scripts/build-router-performance PROFILE OUT_DIRECTORY` builds each profile
from pinned sources. The delivered `combined` profile enables:

- High-throughput four-core schedule (`R5S_ROUTER_SCHEDULE=high-throughput`).
- Datapath batch 16, B51 RX/TX batch 16, B51 ring 128 descriptors.
- Direct WAN fast path, queue cache-line padding, Cortex-A55 Rust/C codegen.
- TX/RX checksum requests on WAN, LAN1, LAN2 and driver TSO on all three ports.

The `multicore` profile (linear NAT lookup, original budgets) is the rollback
comparison. `cpu`, `dma`, `hardware`, `tso`, `gro-tso` and `qualification`
profiles remain available for targeted A/B runs; the full A/B switch list is in
the performance document. Two identical builds must match byte-for-byte; they
did. No known-good image was overwritten.

## 4. Implementation summary

### 4.1 Optimizations delivered (workstream map)

- **A — four cores**: high-throughput budgets, per-core NAT workers with
  flow-affinity steering and worker-local tables, load-aware new-flow
  assignment, measured CPU/worker telemetry (`cpu.*` in the B51 status reader),
  multicore profile retained for rollback.
- **B — batching**: bounded multi-frame RX and batched TX with completion
  reclamation on RTL8125 and GMAC, configurable batches 8/16/32/64, batched
  logical-LAN/dispatcher/worker drains, WAN loop caps removed, empty-to-nonempty
  notification coalescing with rearm latch (no lost wakeups).
- **C — NAT fast path**: hash-indexed outbound/reverse/endpoint lookups,
  per-worker slot and port allocation cursors with stride-4 shard lanes and
  preserved reuse delays, incremental 8-slot expiry, direct GMAC→worker WAN
  ingress and worker→GMAC/worker→LAN optional egress bypasses with lease and
  route revisions.
- **D — zero-copy/DMA**: shared 512×2 KiB generation-tagged pool with the
  documented FREE→RX_DMA→CPU→TX_DMA→FREE ownership machine, word-level atomic
  free-bitmap allocation, barrier strategy selectable (`full`/`outer`),
  write-back vs Normal-NC payload option with explicit cache maintenance,
  reference-based forwarding with copy fallback and zero-copy counters.
- **E — hardware acceleration**: GMAC PBL 8/16/32, PBLX8, RK3568 AXI
  programming, EAME (DMA_SysBus_Mode bit 11), HW_FEATURE0-3 discovery,
  capability-gated second TX/RX channels, hybrid RX IRQ; RTL8125 rings 64-512,
  V3 descriptors, RSS with indirection table, optional 2/4 RX queues and a
  second polled TX queue, MPS/MRRS control with live link read-back; checksum
  offload integrated with NAT on all three ports; driver TSO with software
  fallback; guarded guarded-SD deployment preserved.
- **F — GRO/GSO/TSO**: optional worker TCP pairing and driver-side adjacent
  pairing with strict compatibility checks, bounded hold/flush, egress GSO
  aggregation with software segmentation default and hardware TSO opt-in.
- **G — platform**: Cortex-A55 opt-level 3, single codegen unit, LTO, pinned
  target JSON; separate debug/release/benchmark SDK configurations; read-only
  CPU/DDR/GMAC clock reporting; cache-line separation of queue cursors and
  hot counters.
- **H — measurement**: per-stage counters in the B51 UDP schema (304+ words,
  step-down for older query sizes), host datapath benchmark
  (`scripts/benchmark-router-host`, `tests/datapath_benchmark.rs`), board
  benchmark with iperf3/ping/latency/diagnostic capture
  (`scripts/benchmark-router-board`), per-feature A/B switches.
- **I — tests**: networking, DMA ownership/concurrency, offload, scheduling and
  regression suites (section 6).
- **J — artifacts**: reproducible profiles, byte-identical repeat, image
  verification, checksummed deployment bundle.
- **K — validation support**: board test procedures, benchmark scripts,
  guarded `scripts/flash-sd` (dry-run default, device identity checks).
  Physical execution is manual and unrun.

### 4.3 Session-final changes in this delivery

- NAT allocation cursors: per-worker slot cursor and port cursor with
  collision-safe reservation, stride-4 shard lanes and reuse-delay semantics
  (`router-core/src/nat.rs`), three new unit tests.
- EAME: `R5S_GMAC_EAME` build option with revision gate (0x40-0x52),
  read-back verification and fallback (`drivers/gmac0/dma/dma.c`,
  `pds/gmac_dma_corrected/build.rs`), diagnostics (`dma_capabilities.eame`),
  host tests, enabled in `qualification`, off in `combined` pending board A/B.
- VLAN hardware acceleration documented as inapplicable to the untagged-subnet
  workload (VLAN-hopping hazard if RX strip were enabled without VLAN-aware
  forwarding); tagged frames already drop safely
  (`router-core/src/ethernet.rs:220`).
- Regression completeness: `tests/wan_retry.rs` added to the
  `tests/wan_lan_ingress` cargo suite; `tests/tso_lan_test.rs` and
  `tests/gmac_queue_test.rs` wired into `scripts/test-router-integrated`.
- TSO group contract fix: a non-continuing reference mid-group is consumed and
  freed with the rejected burst (`pds/pcie_provider/src/b51.rs`,
  `tso_group`), matching `tests/tso_lan_test.rs` (110/110 host tests).

## 8. Deployment (manual, guarded)

1. Verify the bundle: `sha256sum -c SHA256SUMS`, then
   `python3 scripts/verify-image candidate/r5s-rtl8125-lan-repair.img`.
2. Identify a removable test SD; confirm CID, model and byte capacity; leave
   the Ubuntu recovery eMMC untouched. Follow [sd-writing.md](sd-writing.md).
3. Dry-run `scripts/flash-sd --device DEVICE --image IMAGE --profile r5s
   --expect-serial CID --expect-model MODEL --expect-bytes BYTES`, review the
   device identity, then repeat with `--execute` for the selected test SD only.
4. Boot, verify WAN DHCP, both LAN links/DHCP, ICMP, NAT and B51 diagnostics at
   `10.44.1.1:48125`, then run the benchmark matrix. Capture serial logs on
   fault. Restore the known-good SD or remove it for eMMC recovery.

No step of this workflow writes any device from the build host.

## 9. Remaining risks and limitations

- Every board-facing result is unmeasured: forwarding rates, four-core
  utilization, DMA visibility under load, offload wire behavior, RSS queue
  spread, hybrid IRQ latency, write-back cache integrity, direct-egress
  ordering, link-flap recovery and sustained 60-minute stability.
- Optional paths (R51 second TX queue, GMAC second channels, worker LAN/WAN
  egress, GRO-TSO, write-back payloads, MPS/MRRS changes, EAME) require the
  board qualification sequence before production use; defaults keep them off in
  `combined` except those already listed in the profile table.
- B51 MSI-X interrupt moderation is blocked by the missing ARM GIC ITS service
  in the native image; bounded polling is the implemented alternative.
- Dedicated DDR and thermal telemetry need additional platform evidence.
- Host tests cannot prove real DMA coherency; the software ownership model is
  verified, hardware behavior is not.
