# RTL8125 B51 Linux and Realtek comparison

## FriendlyARM board baseline

### TX descriptor format in the No Close trial

The first native v3 service trial still failed DHCP. Only the service image was tested. The one-frame diagnostic outcome, peer capture and point of failure remain unknown.

FriendlyARM `rtl8125_hw_config` sets MAC OCP `0xeb58` bit 0 for the new TX descriptor format. Its `struct TxDesc` contains opts1, opts2, the 64-bit payload address and four reserved dwords. `rtl8125_alloc_tx_desc` reserves one additional entry, `rtl8125_init_ring` clears the allocation and `rtl8125_start_xmit` indexes descriptors at a 32-byte stride. A single untagged, unfragmented frame has the same first four dwords as the legacy format. [Register selection](https://github.com/friendlyarm/r8125/blob/3fda70ebcba22f281ec4e3a69c355992c8823fc0/r8125_n.c#L18310) · [TX structure](https://github.com/friendlyarm/r8125/blob/3fda70ebcba22f281ec4e3a69c355992c8823fc0/r8125.h#L2044) · [Allocation](https://github.com/friendlyarm/r8125/blob/3fda70ebcba22f281ec4e3a69c355992c8823fc0/r8125_n.c#L17856) · [Publication](https://github.com/friendlyarm/r8125/blob/3fda70ebcba22f281ec4e3a69c355992c8823fc0/r8125_n.c#L19964)

The first native v3 images kept the Linux-style 16-byte layout and explicitly verified bit 0 clear. The updated v3 path selects and verifies bit 0 set before enabling bus mastering, clears the reserved words and guard entries, and programs the relocated RX ring base. Classic TX retains the legacy layout. Both original native settings agreed with their own ring stride. The source establishes a difference from the board driver, but leaves open whether No Close can operate with either format.

The live LAN1 debug dump confirms `HwSuppTxNoCloseVer=0x3` and `EnableTxNoClose=0x1`. The Linux baseline therefore uses tail-pointer submission and close-pointer completion. A controlled comparison with the same Linux driver using OWN/TxPoll and a peer capture would test whether classic TX works on this board.

The reported module version `9.016.01-NAPI-g3fda70e` matches FriendlyARM commit `3fda70ebcba22f281ec4e3a69c355992c8823fc0`. Its Makefile derives the suffix from the checkout. On LAN1 (`eth1`, `0000:01:00.0`, BAR2 `0xf4200000`), Linux reported 1 Gb/s full duplex, 56 transmitted packets and zero received. This sample contains no peer capture. Both endpoints reported correctable PCIe receiver and timeout flags with no uncorrectable completion timeout. The snapshot cannot date those flags.

FriendlyARM defaults `ENABLE_TX_NO_CLOSE=y`. Method 5 supports no-close version 3. With it active, `rtl8125_hw_config` sets TxConfig bit 6, `rtl8125_doorbell` writes a 16-bit software tail pointer, and completion uses the hardware close pointer. The native classic profile verifies bit 6 clear and uses OWN/TxPoll. The v3 profile verifies bit 6 set. The board module's live selection can be read from `/proc/net/r8125/eth1/debug/driver_var` when built with proc debugging. Changing only the doorbell or completion test would mix the two protocols. [FriendlyARM source](https://github.com/friendlyarm/r8125/blob/3fda70ebcba22f281ec4e3a69c355992c8823fc0/r8125_n.c#L19917) · [Build defaults](https://github.com/friendlyarm/r8125/blob/3fda70ebcba22f281ec4e3a69c355992c8823fc0/Makefile)

The sequence comparison uses Linux v6.12, commit `adc218676eef25575469234709c2d87185ca223a`, with a cross-check against Linux master at `c44104f3642da720164042623e4832836aefdd8e`. Realtek is `7a5b9713043cef55ebb8433e722141e6ba2ab6fd`. R5S admits PCI `10ec:8125`, revision `05` and TxConfig signature `64100000` as `Method::B51`. Linux `rtl8169_get_mac_version` matches XID `0x641` as `RTL_GIGA_MAC_VER_63`. Realtek `rtl8125_get_mac_version` splits the signature into `0x64000000` and `0x00100000` and selects `CFG_METHOD_5` for this PCI device. [Linux v6.12 Realtek source tree](https://github.com/torvalds/linux/tree/adc218676eef25575469234709c2d87185ca223a/drivers/net/ethernet/realtek) · [Linux master r8169](https://github.com/torvalds/linux/blob/c44104f3642da720164042623e4832836aefdd8e/drivers/net/ethernet/realtek/r8169_main.c) · [Realtek vendor source](https://github.com/RealtekNIC/Realtek-RTL8125-Series-driver/blob/7a5b9713043cef55ebb8433e722141e6ba2ab6fd/src/r8125_n.c)

| Area | Linux and Realtek evidence | R5S assessment |
|---|---|---|
| PCI setup and DMA | Linux `rtl_init_one` enables the device, selects a DMA mask, maps a memory BAR. Linux enables mastering in `rtl8169_up`. Vendor `rtl8125_init_board` performs PCI resource setup. Both use PCI DMA mapping APIs. | R5S verifies the translated BAR and stages root/endpoint command writes. Mastering is enabled after programming the private rings and window. The high byte of endpoint config dword `0x70c` controls L0s/L1 entry latency. Linux `rtl_set_aspm_entry_latency` writes `0x27` at byte `0x70f` or uses the same dword mask as R5S through CSI. Realtek’s `_rtl8125_set_l1_l0s_entry_latency` preserves the top two bits and sets the low six to the same value. |
| Reset and OOB | Linux `rtl_hw_reset`, vendor `rtl8125_exit_oob` and `rtl8125_nic_reset` coordinate MAC stop/reset. | `mac::reset` checks FIFO/idle and reset completion. B51 also waits for the shared FIFO and PHY readiness. Reset and PHY errors keep distinct LED outcomes. |
| CPlusCmd | Linux retains `CPCMD_MASK=0x2063` in `rtl_init_one` and writes with a 16-bit access. Vendor `rtl8125_hw_config` clears its debug, force and ASF fields with a 16-bit RMW. | Preserved prior correction for the supported bits and readback. RTL8125 RxConfig controls VLAN stripping separately. |
| 0x4500 RSS control | Linux v6.12 `rtl_hw_start_8125_common` issues an 8-bit zero store. Current Linux `rtl_hw_start_8125_common` and the single-ring branch in `rtl_hw_start` issue 32-bit zero stores to `RSS_CTRL_8125`. Realtek `rtl8125_hw_config` also uses a 32-bit zero store when RSS is disabled. | Use one dword zero before locking configuration and enabling DMA. Remove the byte write and the full-dword equality requirement. The model checks the width, value, configuration lock and bus-master ordering. |
| ChipCmd, TxConfig and RxConfig | Linux `rtl_hw_start` writes bases, commits posted MMIO, enables TX/RX, then calls `rtl_init_rxcfg`, `rtl_set_tx_config_registers` and adjusts filters. Vendor `rtl8125_hw_start` enables engines after setup. | Normal LAN uses `ChipCmd=0x0c`, `TxConfig=0x03000700`, `RxConfig=0x40000f0a` and readbacks. Diagnostic enables TX alone with `ChipCmd=0x04`. |
| PHY, link and firmware | Linux `rtl8125b_hw_phy_config` applies `rtl8125b-2.fw` via `r8169_apply_firmware`. Vendor uses `rtl8125_hw_phy_config_8125b_2`. | Existing B51 interpreter and version `0x0016` requirement stay active. MDIO, EPHY and OCP paths have bounded polling. R5S requires PHY autonegotiation and MAC carrier, then independently checks engine activation and DMA. |
| OCP and EPHY waits | Linux uses width-specific `r8168_mac_ocp_*`, `r8168_phy_ocp_*` and `rtl_ephy_*` accessors, with operation-specific waits and readback/commit at MMIO boundaries. | `Chip::ocp`, `ephy`, `phy` and `firmware` implement the local access sequence. A successful sequence establishes the specified observations only. No timing or method-table edits were made without evidence. |
| Rings, format and DMA addresses | `rtl_set_rx_tx_desc_registers` sets high before low. Linux `TxDesc` and `RxDesc` use four little-endian dwords. `rtl8169_start_xmit` publishes fields before OWN. Vendor `rtl8125_init_ring` and `rtl8125_start_xmit` support method-specific extensions. | Classic TX and RX use aligned 16-byte descriptors. The updated v3 TX ring uses 32-byte descriptors. Both profiles use one queue, translated addresses and ring-base readback. |
| TX doorbell and completion | Linux `rtl8169_doorbell` writes 16-bit bit 0 to `0x90`. `rtl_tx` reclaims slots after OWN clears. The vendor TX path and `rtl8125_tx_interrupt` include hardware TX close modes. | Classic TX uses Linux-style poll and OWN completion. The v3 trial uses queue-0 tail and close pointers with separate submission, completion and timeout observations. Physical delivery requires a peer capture. |
| Interrupts | Linux enables device IRQs and runs NAPI from interrupt handling. Vendor has method-specific IRQ masks and handlers. | Polling profile masks device interrupts and reads MAC status. Diagnostic also snapshots both PCI Command/Status dwords before shutdown. |

The confirmed software discrepancy in this iteration is the mixed-width duplicate write and overbroad readback at `0x4500`. A hardware startup failure at that register has not been observed. The earlier CPlusCmd defect remains fixed. No evidence establishes either as the cause of the physical TX failures.
